Privacy policy

Last updated: 14 September 2026

This policy covers two things: this website and the Sakura application. The short answer is the same for both: whoever maintains Sakura receives no personal data from you, because neither the website nor the application sends any to a project server. That server does not exist. What does leave your machine, and where it goes, is listed below without exceptions.

Who maintains Sakura

Sakura is an open source project maintained by EXO. Nothing is sold and there are no user accounts. The contact channel is the repository issue tracker, which is public.

1. This website

What it collects

Nothing. The website has no analytics, tracking pixels, advertising, forms, social media buttons or embedded videos, and loads no fonts or scripts from other servers. It sets no cookies.

Hosting: GitHub Pages

The website is served by GitHub Pages, a service of GitHub, Inc. According to GitHub's own documentation, when a GitHub Pages site is visited, the visitor's IP address is logged and stored for security purposes. GitHub does that logging and controls it; the project has no access to it. It is governed by the GitHub General Privacy Statement.

Downloads

The installer and the zip are downloaded from the releases published on GitHub. When you press a download button your browser connects to GitHub's servers, and the same privacy statement applies.

What your browser stores

Only the language you pick with the ES/EN switch, and only if you press it. It is explained in the cookie policy.

2. The Sakura application

What stays on your machine

  • Microphone audio. Wake word detection (Vosk) and transcription (Whisper) run on your machine, against models stored on your disk. There is no cloud speech recognition.
  • Whatever is read from the screen and the clipboard, unless you send it to a cloud AI provider yourself (see below).
  • Screenshots you save and screen recordings, in your Pictures and Videos folders. A recording includes system sound and, only if you tick it, the microphone; it is made on your machine and Sakura does not send it anywhere.
  • Your application data — tasks, routines, focus sessions, conversation history and settings — is stored under %LocalAppData%\Sakura, inside your Windows user account. Personal memory (which ships switched off) and AI provider keys are additionally encrypted with Windows DPAPI.

The application has no telemetry, analytics, crash reporting or usage measurement of any kind. None of it exists in its code, which is public.

What leaves your machine

  1. Update check. Automatic, and only in the copy downloaded from GitHub: the Microsoft Store version is updated by the Store. At most once every 24 hours, Sakura reads the public release list on api.github.com. It sends no identifier and no information about your machine beyond what any connection carries (your IP address). It can be switched off in Settings. Nothing is installed unless you accept it.
  2. The transcription model, the first time you use voice. Sakura downloads the Whisper model once (about 140 MB) from Hugging Face and stores it on your disk, so dictation works offline. It only requests the file; nothing of yours is sent. In version 0.30.0 this download happened the first time Sakura opened, even if voice was never used; from 0.30.1 on it waits until you use it.
  3. Downloads you ask for. The wake word model (from alphacephei.com), when you turn on or test «Oye Sakura»; Ollama, if you let Sakura install it from GitHub (the Microsoft Store version does not install it: it only links to its website); and the language models you choose to download, which Ollama fetches from its own registry.
  4. Cloud AI providers, only if you configure one. None is active by default. If you choose one (Anthropic, OpenAI, Google Gemini, Groq or OpenRouter), it receives the conversation text and, when you use Lens, the screen translator, «Preguntar a Sakura» with a screenshot or Ctrl + Shift + Espacio to explain a window, the image or text from the screen after anything that looks sensitive has been masked. Never the audio. What that provider does with it is governed by its own privacy policy. With Ollama on your own machine nothing leaves.
  5. Images for your presentations, only if you allow it. When an answer asks for a slide image and you save it as a PowerPoint file, Sakura can look it up on Wikimedia Commons, where images are freely licensed. It is off by default and Sakura asks the first time; only the search term leaves your machine, and the deck credits each image's author and licence.
  6. Sources for your drafts, only if you allow it. When you save a draft, Sakura can look up real work on its topic in two public academic catalogues, OpenAlex and Crossref, to leave you the reference list. Only the topic leaves your machine, never the contents of the document.
  7. Network commands you ask for. For example, the «Comprobar si hay conexión» command (check whether there is a connection) runs a ping to 1.1.1.1.

The technical detail, with the exact addresses and a link to each provider's policy, is in docs/PRIVACY.md (in Spanish, with an English summary).

Deleting your data

Personal memory can be read and wiped entirely from inside Sakura. Everything else lives under %LocalAppData%\Sakura: deleting that folder deletes your application data.

3. Your rights

Data protection laws — the GDPR in the European Union, Mexico's Federal Law on the Protection of Personal Data Held by Private Parties, and others — give you the right to access, correct and delete your data, and to object to its use. Because the project keeps no data about you, there is nothing to hand over or delete on our side. Rights over data held by GitHub or by the AI provider you choose are exercised with them. If you have any question, write to us through the contact channel.

4. Children

Neither the website nor the application collects data from anyone, children included. If a child configures a cloud AI provider, that provider's age requirements apply.

5. Changes

If anything about what leaves the machine changes, this page is updated in the same change and the date above changes with it. The full history is in the repository.
